# Executable development in the rural body

The software-improvement evaluator was inspected after the 1D-to-2D embodiment
change. A prospective qualification now exercises the complete existing finite
practice-code loop in the actual rural body, rather than inferring compatibility
from earlier one-dimensional tests.

Three explicitly branched individuals (seeds 201–203) receive an externally placed
unfamiliar two-press object three cells away. Each autonomously approaches it,
experiences partial progress, requests a practice-policy revision, rejects a
candidate that fails a regression, and retains a passing executable policy.
A second externally arranged object changes from two-press to four-press after
an observed effect. Each individual diagnoses a further limitation and retains
a distinct progress-sensitive policy after testing it. The policy itself is
executed during subsequent action selection.

Each selected candidate passes every required evaluator profile; rejected
candidates retain their failed cases and untested-coverage status. Evaluator
branches have distinct explicit lineage, and their test events contain actual
world-motion records. The main test individual's identity, branch and event
prefix survive both implementation changes. Previously learned behavior is
then demonstrated on a different target of the first observed type.

A twelve-tick continuation runs in a separate Python process from the saved
checkpoint. Its final state must exactly match both uninterrupted execution and
an in-memory restored continuation. Before/after checkpoints, policy source,
branch-test events and receipts are retained under validation/world-self-development.
The executable entry point is examples/persistent_individual/world_development_probe.py.
Earlier contact-only and in-memory-only panels remain as intermediate evidence.

## Scope and remaining gaps

The experiment arranges the opportunities; it does not demonstrate that the
creature creates its own increasingly difficult curriculum. Three seeds share
the same setup, so they do not establish broad environmental generalization.
No simulated experience or candidate policy was installed in the live companion.
The live companion still had zero executable revisions when this investigation
began; these are separate prospective qualification individuals.

The candidate language remains an authored finite Python practice-policy language.
This is actual executable revision, but does not demonstrate general source-code
editing, improvement of the brain architecture, or open-ended intelligence.
Required regression profiles are authored. Prior failed profiles influence test
order through the existing evaluation-memory mechanism; this panel does not
independently establish a further improvement to that mechanism.

The result rules out a suspected basic incompatibility between the evaluator and
the new body. The next substantive gap remains generality and useful initiation
in sustained ordinary life, not more demonstrations of this same finite loop.
