# V17: predicting the effect of a practice-code change

The developmental request already distinguishes its actual stopping rule from
its current executable policy. After teaching, the actual stop can be a supplied
attempt allowance. V17 additionally exposes the observed trials, visible changes
and consecutive no-change count from that same goal.

Before running a candidate in a test branch, the evaluator executes its stopping
function on those recorded counts. If it would still make the same stop, the
candidate is rejected as not changing the identified decision. The receipt keeps
the original stop, candidate hash, inputs and source evidence event. The outcome
is explicitly an executable counterfactual, not a new real experience or a
prediction that the entire future activity will succeed.

A candidate that changes the recorded decision still needs every required branch
profile. No regression requirement is removed. Rejections without branch tests
retain an empty cases list, all profiles marked untested, and the coverage label
rejected-by-recorded-stop-counterfactual. They are not counted as failed empirical
profiles in the learned test-order memory. Existing consumers report rejected
candidates and passing branch-test counts separately.

The qualification begins with actual delayed-device interaction. Three unaided
attempts fail; the creature requests assistance. Four extra attempts supplied by
a person produce one visible change but exhaust the allowance at seven trials.
The creature then initiates software review. V17 predicts that two candidates
would still stop on the recorded state, rejects them, and tests the remaining
progress-sensitive candidate. It passes all eight profiles and the actual goal
subsequently completes. Prior teaching remains attributed to its own observed
outcome, not to success after software replacement.

## Scope

This is an operational distinction between recorded experience, an executable
rule, a supplied allowance, a counterfactual, and test-copy outcomes. Its effect
on candidate selection is demonstrated. The program evaluator and counterfactual
mechanism are authored support, not a learned general theory of the creature's
implementation or a creature-authored improvement to its evaluator. The finite
practice language, candidate generator and mandatory regression profiles remain
limitations. Pause, rollback and general migration understanding are not
established by these checks. The full end goal remains unfinished.
