# Bounded executable practice revision, v1

This protocol is frozen before the prospective panel (seeds 81–84). It tests a
limited authored development mechanism, not general code understanding.

Each individual encounters a device with opaque type and a real two-press switch
implementation. Food is hidden. No external lesson, candidate choice or patch
request is supplied after development is enabled. Geometry alternates left/right
at contact distance. The total-attempt rule should stop after three presses with
one visible change. Its own review must originate a request grounded in those
observations and its active source rule.

Two generated Python programs are evaluated: a six-total-attempt rule and a
three-consecutive-no-progress rule. The latter changes which observation counter
governs executable behavior. The program language, diagnosis template, generator
and evaluation suite are authored initial structures. The creature does not edit
arbitrary files or understand arbitrary software.

Each candidate is tested on explicit branches: the unfinished original goal,
a fresh switch, counter, two-press switch, three-press switch, and an inert device.
Productive cases must reach two visible changes within 32 ticks; inert practice
must stop within three attempts. Automatic development is suppressed and recorded
on evaluation branches. Tests preserve source, branch provenance and raw events.
The extended-total rule must fail the inert regression; the consecutive rule must
pass all six cases before adoption. The parent must preserve its exact prior
history and lineage, advance only one actual tick, and finish its unfinished goal.
No test experience counts as the parent's demonstrated skill.

Save before/after checkpoints and generated source. Restore after adoption and
verify continued source and review equality. Existing continuity, learning,
rehearsal, adverse-result and body tests are separate regression evidence. This
suite does not establish preservation of every possible prior skill or sustained
companionship. Repeated useful changes and improvement of development itself
remain separate unqualified goals.
