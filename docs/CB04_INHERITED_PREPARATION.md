# CB-04 optional inherited preparation profile

`examples/persistent_individual/inherited_preparation.py` provides an explicit host-side research profile. It does not alter `DefaultBrain` construction, gain-1 feedback, or the baseline individual's checkpoint. A fresh age-stage-1 individual must contain exactly 29 expressed inherited instinct records, no previously processed instincts, zero brain ticks, no pending inputs or outcomes, and the same decoded owner-provided program. The profile sets chemical 213 to 1, executes one full `train_instincts` pass, returns chemical 213 to 0, and clears activity, matching the existing declared demo procedure. It processes inherited preparation separately from acting and receiving food outcomes; this is not a native Docking Station sleep-parity claim.

Preparation happens transactionally on a cloned brain. Its receipt records the profile, program and brain-definition digests, identity, seed, age and sex, record and matched-decision counts, per-record results, brain tick and RNG before and after, full chemistry and pending lobe inputs, and hashes of both brain states. The prepared brain retains the resulting state and time. The receipt does not assert that any subsequent action or task will succeed.

The API prepares a fresh adaptive motor individual once using `prepare_inherited(individual, program_path)`. `clone_prepared_motor(individual, condition)` creates a `normal`, `effort`, `baseline` or `candidate` arm from that exact post-preparation brain and RNG state. Clone creation requires that the source has not advanced; it never rehearses again. A prepared individual rejects direct legacy `snapshot`, `motor_snapshot`, `save` and `save_motor` operations because they omit the profile receipt. Use `prepared_snapshot` / `restore_prepared` or `save_prepared` / `load_prepared` instead. The distinct envelope carries the receipt and the correctly typed complete inner checkpoint; restore does not invoke preparation and rejects a conflicting identity, definition or rehearsal state. The file-save path uses a synced temporary file, atomic replacement and a directory sync.

The protected public methods prevent an accidental ordinary save from silently losing the receipt. A caller can deliberately extract the inner `state` from an envelope or explicitly invoke an old class implementation, bypassing this profile; that is not a supported prepared checkpoint or evidence of exactly-once preparation. The unchanged legacy loaders are not retroactively able to recover metadata they were never given.

`tests/test_inherited_preparation.py` checks the boot result against the declared existing procedure, identical four-arm brain/RNG states, repeated-preparation and receipt-conflict rejection, blocked untyped checkpoint methods, JSON continuation and an actual process restart without repeating rehearsal. These are profile and persistence tests. The later [development qualification](CB04_PREPARED_DEVELOPMENT_RESULTS.md) and [prepared fresh comparison](CB04_PREPARED_FRESH_RESULTS.md) report separate population evidence and limitations.
