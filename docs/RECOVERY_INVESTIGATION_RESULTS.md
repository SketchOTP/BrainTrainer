# Developmental v8: recovery failure changes activity

The earlier maintenance drive stopped after three failed rests and never revisited
that conclusion. Even after external repair, it remained unable to recover and
finish its interrupted activity. V8 retains the failed goal, asks for investigation
once, holds still for eight actual ticks between recovery probes, and resumes rest
when a probe demonstrates positive recovery. Once adequate reserve is observed,
the same unfinished learning goal can resume.

The new intrinsic hold action has an actual completed `held` outcome and neither
moves nor replenishes reserve. It is explicitly adopted with v8. Earlier versions
retain their previous action semantics. Rest and hold are distinct operations;
waiting, pausing and dreaming do not create recovery evidence. The observed recovery
rate remains learned from real rest outcomes, while the initial thresholds, probe
interval and strategy are authored.

## Prospective comparison

The frozen protocol in RECOVERY_INVESTIGATION_PROTOCOL.md used four seeds, each
with v7 and v8 and both persistent-failure and external-repair conditions (16 cases).
All eight v8 gates passed. In all four persistently broken cases, v8 requested help
once, retained .03 reserve, made four later probes and kept the cause unresolved.
In all four repaired cases it observed recovery, completed maintenance and finished
its original learning goal. The eight v7 controls did not recover or finish that
goal, including the repaired cases. Every case's restoration during investigation
matched subsequent actual events, complete state and review.

External repair changed the body's rate, not the creature's claimed knowledge.
The goal remained unresolved immediately after that intervention. Only a later
actual outcome established returned recovery. Repair remains attributed to the
external actor; no self-repair or implementation diagnosis is claimed.

Raw cases, runner and results: `validation/recovery-investigation/`. A separate
16-tick continuation of a v7 checkpoint under preserved prior and current code
produced identical complete state hashes. The first comparison attempt mixed old
brain code with the new envelope and failed on a missing capability name; the
corrected comparison loaded the matching preserved envelope as well.

## Integration and evidence boundaries

The habitat displays recovery requests separately from practice guidance and hides
the irrelevant practice controls. Browser accessibility inspection of an explicit
research fork showed the actual waiting state, recovery request, three failed rest
moments, unknown cause, pending learning goal and test-branch label. No browser
interaction advanced that individual; its qualification server was then stopped.

The main visible v6 companion remains unchanged, paused and durable at tick 93.
All 267 pinned original files remain unchanged. This candidate is not deployed.

This is a bounded authored investigation and assistance strategy. It does not
identify the underlying defect, perform a repair, learn better probe scheduling,
or improve its own developmental process. Those remain necessary work toward the
full goal, along with richer embodiment, relationship and sustained companionship.
