# V19: learned response timing and further executable development

Earlier practice development stopped considering code changes after adopting the
progress-sensitive rule. That left a fixed four-attempt post-progress bound as a
permanent stopping point. A slower activity could produce an actual useful
effect with teaching, then exhaust its allowance without another code-review path.

V19 records response gaps from matched, completed interactions with observed
appearance changes. A gap counts actual practice attempts since the last change;
it is not elapsed wall time or an inferred device setting. The curriculum owns
these counts and their evidence events. A goal and its activity type retain the
largest observed successful gap. A new target of that type receives the timing
evidence but must still demonstrate its own effect.

The executable language now also admits a bounded rule using this observed gap
plus a candidate margin. With no timing evidence, unfamiliar objects retain the
three-attempt stopping bound. With evidence, the candidate can allow a longer
practice interval appropriate to that type. Its total threshold is capped at 32.
Calls, imports, arbitrary host access and other executable forms remain excluded.

When the fixed progress-sensitive rule becomes inadequate, the creature can
propose a uniform longer bound or a gap-sensitive rule. The latter rule is not a
terminal state: a later limitation can initiate another evaluated margin change.
Recorded-state counterfactuals and all required branch regressions still apply.
The accepted program must preserve the short bound on unfamiliar inert objects
and the bounded response to activity that becomes inert after making progress.

then runs out. The creature initiates review, rejects a uniform longer-wait

A further test changes a new activity from an immediate response to a response
requiring three attempts after initial success. The creature must identify the
new limitation, test another change, and preserve the earlier five-attempt skill.
This specifically checks that the new program family does not introduce another
hard-coded prohibition on subsequent improvement.

## Limits

Candidate forms, margin proposals and the regression suite are still authored.
This expands a finite program family; it is not arbitrary software modification
or proof of a generally improving intelligence. The environment and teaching
are externally arranged, while requests, candidate evaluation and adoption arise
inside the creature's continuing activity. The recorded maximum gap is a bounded
experience-based practice allowance, not certainty that a new target will behave
identically. Prior behavior still requires verification after changes.

Test histories remain separate from the ordinary live companion. The full end
goal remains active and unfinished.
